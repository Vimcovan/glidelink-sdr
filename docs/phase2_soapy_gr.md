# 第 2 阶段：Soapy 与 GNU Radio

对应设计文档 7.2、7.3 节与第 9 节第 2 阶段。验收标准：

1. 在 GNU Radio 中修改快速 AGC 参数并重新初始化；
2. 读写任意 AD9361 寄存器；
3. PC 经网络使用板子。

## 1. 决定

| 编号 | 内容 | 决定 | 理由 |
|---|---|---|---|
| E1 | 驱动参数的访问 | 经 libiio 的调试属性（debugfs）读写，名字与设备树属性相同；`initialize` 设置项触发驱动重新初始化 | 驱动已把设备树参数全部放在 debugfs，写入后由 `initialize` 生效；调试属性经 iiod 也能访问，板上与网络一套代码 |
| E2 | 重新初始化后的状态 | Soapy 模块在初始化前记下频点、采样率、带宽、端口、增益模式与增益，初始化后写回；自上次初始化以来写过对应设备树参数的项以设备树参数为准 | 驱动初始化把这些都恢复成设备树的值（实测采样率回到 30.72 MSPS、本振回到 2.4 / 2.45 GHz），用户只想改 AGC 参数时不应丢掉其余设置 |
| E3 | 慢操作的超时 | 改采样率、写驱动参数、重新初始化时 libiio 超时临时放宽到 10 s | 经网络时超时会断开与 iiod 的连接；第一次切到低采样率（重新装 FIR）实测 1.35 s，重新初始化约 1 s |
| E4 | 自动增益 | `setGainMode(true)` 只在手动时切到 `slow_attack`，已在某种自动增益模式时不变；自动增益下写 RX 增益被忽略 | gr-soapy 构造时总会设一次增益模式与增益，否则会覆盖经设置项选的 `fast_attack`，或因芯片拒绝写增益而报错 |
| E5 | 路由 | Soapy 启动流时保留用户设好的路由，只在主机端口 0 的路由为空时接回射频 | 第 3 阶段卸载模块时路由由连接管理决定（射频 → 槽位 → 主机），流的启停不能把它改回直连 |
| E6 | 主机端口 1 的流 | Soapy 流参数 `port=1`；32 位字原样作为 CS16；启动时连同直接相连的槽位一起清理 | 模块数据不一定是 12 位射频样点，不做 DAC 对齐；停在包中间的流会在槽位里留下半个包（实测：上一个程序结束后槽位不再出数据） |
| E7 | tuser 标志 | 外壳 1.3.0 起所有端口、两个方向用同一套位：0 此前有丢包，1 突发结束，2 定时发送；主机端口包头的 flags 就是这些位 | 1.2.0 的 TX 包头位 0 是“定时”，经槽位绕回主机 RX 后被读成“此前有丢包”；用户模块接口规范（设计文档 5.1）依赖这些位，在写模块之前统一 |
| E8 | gr-glidelink | 纯 Python 块：控制块（路由、设置、寄存器、回读）与主机端口源 / 汇；射频收发用 gr-soapy | 控制面不在数据通路上，Python 足够；gr-soapy 本身已有设置与寄存器接口，射频流不必重写 |
| E9 | iiod | `load_overlay.sh` 加载叠加后重启 iiod | iiod 0.23 只在启动时扫描设备，开机时叠加还没加载，网络客户端只看到 1 个设备 |

## 2. 实测结果

| 项目 | 方法 | 结果 |
|---|---|---|
| 驱动参数与重新初始化（板上） | `sw/tests/settings_init.py`，TX 板 | 锁定电平 10 → 14，重新初始化 1.9 s（含恢复），寄存器 0x101 = 14；采样率、两个本振、两个带宽、增益模式 `fast_attack`、TX 增益全部恢复；写 `adi,gc-rx1-mode = 0` 后初始化为手动增益；AD9361 寄存器写 0x0B 读回一致 |
| 同上（经网络） | 同上，PC（WSL）`uri=ip:192.168.4.1` | 全部通过 |
| 初始化后的数据通路 | `timed_burst.py`，数字环回 | 定时突发偏移仍为 12 个样点，计数器 0 |
| GNU Radio 中改 AGC 参数 | `sw/tests/gr_agc_init.py`，PC 经网络，gr-soapy 源 2.5 MSPS + GlideLink Control | 运行中锁定电平 10 → 14 并重新初始化（1.7 s），寄存器 0x101 跟随，增益模式、采样率、频点不变；初始化前后接收速率均约 2.5 MS/s；经 gr-soapy 源块写 AD9361 寄存器，控制块读回一致 |
| GRC 示例 | `sw/gr-glidelink/examples/agc_fast_attack.grc`（无界面方式运行） | 流程图正常运行，控制块每秒回读 0x101 与增益模式 |
| 主机端口 1 经 Soapy | `sw/tests/host1_soapy.py`，主机端口 1 TX → 槽位 0 → 主机端口 1 RX | 板上（上一个程序停在包中间之后启动）与 PC 经网络均通过：原始模式、包头模式逐字一致，每次读到的时间戳等于写入时给的时间，无溢出 |
| 外壳 1.3.0 回归 | 两块板：`timed_burst.py`、`ramp_loopback_iio` 50 MSPS 30 s、`settings_init.py`；两板空中 `ota_timed_bursts.py` | 全部通过：定时突发偏移 12 个样点，50 MSPS 全双工逐样点无误；空中 40 个突发间隔标准差 0.010 个样点 |
| 经网络的流 | `SoapySDRUtil --rate`，PC ↔ TX 板 USB 网口 | RX、TX 各 5 MSPS 无丢失；上限约 7.3 MSPS（约 29 MB/s） |

## 3. 已知现象

- gr-soapy 源经网络启动时第一秒内报约 20 次溢出（`sO`），之后稳定；是启动时 iiod 已开始收数、流程图还没开始读造成的。
- 重新初始化会复位 `axi_ad9361`，外壳的异步 FIFO 两侧随之复位，正在传的 RX 包可能被截断；包头模式的接收按包头重新同步，
  初始化后接收速率恢复（`gr_agc_init.py`）。
