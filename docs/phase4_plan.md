# 第 4 阶段：迁移竞赛模块（方案）

对应设计文档第 8 节示例 3–5 与第 9 节第 4 阶段。验收标准：原竞赛系统在平台上以脱机方式运行，指标与竞赛版本相当
（30 fps、时延、PSNR–SNR 曲线，对照竞赛仓库 `data/measurements/`）。

竞赛仓库（`D:\ClaudePrj\deepjsccq-ofdm-fpga`，GitHub Vimcovan/glidelink-fpga）保持冻结：RTL 拷入本仓库并注明来源，不改原仓库。

## 1. 决定

| 编号 | 内容 | 决定 | 理由 |
|---|---|---|---|
| G1 | 模块划分 | 4 个模块：编码器 `jscc_enc`、OFDM 发射 `ofdm_tx`、OFDM 接收 `ofdm_rx`、解码器 `jscc_dec` | 体现多模块串联与逐个卸载；每个模块可单独验证，出错好定位 |
| G2 | 时钟 | 外壳支持每个槽位选自己的时钟（200 MHz 处理时钟、250 MHz、100 MHz），槽位边界做跨时钟 | 编码器的并行度按 250 MHz 选定，物理层按 100 MHz 写成；不改竞赛 RTL 的时序前提。这是平台的通用能力 |
| G3 | 物理层的参考基准 | 迁移后的物理层模块与竞赛 RTL 在同样输入下输出逐比特相同（竞赛 RTL 的仿真输出作为向量）；网络模块仍对整数参考模型逐比特比对 | 竞赛工程没有逐比特的物理层 Python 模型，重写（同步、跟踪环、FFT IP 的定标）工作量大；网络部分已有 `int_ref.py` / `golden_np.py` |
| G4 | PL 内射频样点的幅度 | RX 流化把 12 位 ADC 样点左移 4 位，PL 内两个方向都是 16 位满量程；Soapy 的 CS16 仍为 12 位满量程（由模块内换算） | 模块直接接射频时两个方向一致；主机侧接口不变 |
| G5 | 范围 | 先完成 4.0–4.6；SSCC 基线（LDPC 编解码）与触摸屏 GUI、手机页需要的遥测放到 4.7 | 先拿到验收结果 |
| G6 | 外壳的 BRAM | 主机端口 RX 适配器的包缓存直接改用 URAM；RX / TX 流化改为“小异步 FIFO（LUTRAM）+ 处理时钟侧的 URAM 大缓存”，深度保持 8192（改完后外壳只用 4 个 BRAM36，不再需要按镜像去掉主机端口） | 外壳现用 32 个 BRAM36，竞赛 TX 设计用 104.5 个，相加超过器件的 144 个。改外壳风险小、各镜像都受益；改竞赛网络（权重 ROM 移入 URAM 需要上电写入通路，改 LUT 则 LUT 不够，250 MHz 下 WNS 只有 +0.082 ns）风险大 |
| G7 | 镜像 | 每块板一个镜像：一份配置列出槽位（模块、时钟、参数）与主机端口，生成外壳的槽位连接与工程；TX 镜像 = 编码器 + OFDM TX，RX 镜像 = OFDM RX + 解码器 | 两块板的槽位内容不同；手写外壳顶层不再适用 |
| G8 | 模块中的 IP | 模块说明文件列出用到的 Xilinx IP（`.xci`），构建时加入工程 | 物理层用了 FFT / IFFT、CORDIC、DDS、除法器、相关器、FIFO 等 IP |

## 2. 竞赛工程梳理（4.0）

| 块 | 竞赛工程中的位置 | 时钟 | 输入 | 输出 | IP |
|---|---|---|---|---|---|
| 编码器 | `src/hw/tx/rtl/network`（生成的 `blk_enc_0_latent_idx`） | 250 MHz | uint8 像素（扩成 12 位激活），NHWC | 24 位 `{Q12, I12}` 64-QAM 潜变量符号，帧尾 `tlast` | 无（XPM） |
| OFDM 发射 | `src/hw/tx/rtl/phy/ofdm_tx`、`phy/jscc`（`tx_baseband_jscc`：PN 翻转、组帧、导频、IFFT、前导、URAM 整帧缓存） | 100 MHz | 24 位符号，每帧 32768 个 | 24 位样点 `{Q12, I12}`；竞赛顶层用 20 MSPS 节拍门放行（平台由 TX 流化按 DAC 节拍取数） | IFFT、FIFO |
| OFDM 接收 | `src/hw/rx/rtl/phy/ofdm_rx`（`rx_baseband_top`：帧检测 / CFO、LTF 定时、信道估计、SFO / CPE）、`phy/jscc`（PN 翻转、组帧、URAM 整帧缓存 2.25 帧） | 100 MHz | 20 MSPS ADC 样点 | 24 位均衡后软符号，每帧 32768 个 | FFT、CORDIC ×2、DDS、除法器、复相关器、FIFO |
| 解码器 | `src/hw/rx/rtl/network`（`blk_rx_in_output`） | 250 MHz | 24 位软符号 | uint8 RGB，256×256×3，`tuser` 帧头 | 无（XPM） |
| 射频 | 自写 AD9361 SPI 初始化、TX 正交校准状态机、可编程 FIR、PS 侧快速 AGC 与看门狗 | — | — | — | 平台改用 ADI 驱动：FIR 经驱动加载，AGC 参数经第 2 阶段的设置层，看门狗放进脱机守护程序 |

资源（竞赛，布局布线后）：TX LUT 54,241、BRAM36 104.5、URAM 10、DSP 243；RX LUT 63,699、BRAM36 65.5、URAM 7、DSP 133。
平台（外壳 1.4.0 含 NCO / FIR）：LUT 27,434、BRAM36 39、URAM 0、DSP 90；镜像中去掉示例模块与用不到的端口后会更少。

模块之间的数据格式：符号与样点都用 32 位 `{Q[31:16], I[15:0]}`；12 位量在模块边界符号扩展（符号）或左移 4 位（射频样点，G4）。
每帧最后一拍 `tlast`；OFDM 发射的帧尾另置“突发结束”标志，帧之间的空闲不算欠载；OFDM 接收的帧头 `tuser` 带帧首样点的时间戳。

## 4. 进展与结果

| 项目 | 结果 |
|---|---|
| 4.1 外壳 1.5.0 | URAM 缓存与流化改结构；RX 样点 16 位满量程；槽位独立时钟（`glidelink_slot.v`）；镜像配置与生成（`hw/images/*.yaml`，`hw/scripts/gen_image.py`，含共用源文件库 `uses:` 与 IP 的 `ip_files:`）；模块仿真支持 Xilinx IP（`ip_sim_export.tcl`）与抓取模式。外壳仿真全部通过；`test_clocks` 镜像（NCO 250 MHz、FIR 100 MHz）BRAM 39 → 4、URAM 8，时序收敛；板上 50 / 30.72 MSPS 各 100 s 逐样点无误，跨时钟槽位的 NCO / FIR 硬件在环逐字一致，定时突发、驱动参数设置通过 |
| 4.2 OFDM 发射 | 仿真：输入数据与 PRBS 各 2 帧，帧结构、前导逐比特、帧间空白正确，65536 个符号判决全对。板上（`phy_test` 镜像，100 MHz 槽位，20 MSPS，数字环回，`sw/tests/phy_loopback.py tx`）：3 个完整帧背靠背，前导逐比特一致，数据全对（最大误差 2.5，星座间距 316） |
| 4.3 OFDM 接收 | 仿真：发射模块的输出加噪声输入，2 帧 65536 个符号判决全对，EVM −39.4 dB。板上（发射 → 数字环回 → 接收 → 主机端口 1，`phy_loopback.py txrx`）：357.6 帧/s（空口满速），8 帧判决全对，最差 EVM −46.7 dB |
| 4.4 编码器 | 竞赛编码器 RTL 原样拷入（共用的网络 RTL 放在 `nn_common`），外加字节拆分与寄存器；镜像 `tx`（编码器 250 MHz、OFDM 发射 100 MHz），布局布线后 LUT 61 %、BRAM36 105、URAM 18、DSP 263，时序收敛。仿真：1 幅图的 32768 个符号与整数参考模型逐比特一致。板上（主机端口 1 → 编码器 → 主机端口 1，`sw/tests/enc_hil.py`）：4 幅图（照片、示意图、噪声、全白）循环 60 帧，逐字与参考模型一致，含两个方向 DMA 的端到端 36.6 帧/s |
| 4.5 解码器 | 竞赛解码器 RTL 原样拷入（共用部分即 `nn_common`），外加字节打包与寄存器；参考模型只运行整数模型中解码器的部分，可对任意软符号解码；镜像 `rx`（OFDM 接收 100 MHz、解码器 250 MHz），LUT 42 %、BRAM36 48、URAM 14、DSP 155，时序收敛。仿真：20 dB 噪声下的 1 帧软符号，输出 49152 个字与参考模型逐比特一致。板上（`sw/tests/dec_hil.py`）：4 幅图分别经 30 / 20 / 10 / 5 dB 噪声的软符号循环 60 帧，逐字一致，端到端 40.2 帧/s |

途中发现并改正的问题：

- 异步 FIFO 的格雷码指针只在读写时更新，AD9361 重新初始化时采样时钟的抖动会让二进制与格雷码两份指针不一致；32 深的跨时钟 FIFO 因此卡在“满”（板上 RX 溢出每个样点计一次）。改为每个时钟按二进制指针重算格雷码，抖动后自行恢复（`tb_async_heal`：旧写法卡死，新写法恢复）。
- TX 流化在内部 FIFO 复位展宽期间仍声明就绪，复位刚结束时送入的数据被收下丢掉；改为复位期间不就绪（`tb_tx_long`：比缓存长的突发结束包背靠背全部送出）。
- 流交换的汇一被路由就占住源，即使源还没有数据；改路由要等那个源发完一个包。改为源有数据时才占（`tb_switch_idle`）。停在包中间的汇（如没人读的主机端口）仍需清理：gr-glidelink 的 `set_route` 在路由改变时清理该汇。
- `axi_ad9361` 的 DAC 数据选择开机为 DDS，驱动只在主机 TX 缓冲打开时选外部数据；模块直接接射频时发出的是 DDS 单音。`load_overlay.sh` 加载后把两个 TX 通道设为外部数据（外壳）。
- 复相关器 IP 的系数文件路径在 xci 里是相对路径；镜像生成时把 xci 拷到生成目录并改成绝对路径再导入，仿真导出用同样的拷贝；FIR 编译器 IP 的仿真模型从运行目录读 `.mif`，模块仿真脚本把它拷进去；FFT IP 的仿真模型在 `--debug off` 细化时会误报内部断言，模块仿真改用 `--debug typical`。
