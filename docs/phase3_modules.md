# 第 3 阶段：第一批用户模块（NCO、FIR）

对应设计文档第 5、6、8 节与第 9 节第 3 阶段。验收标准：

1. 仿真与上板硬件在环比对均逐比特一致；
2. 代理块替换后流程图输出不变。

## 1. 决定

| 编号 | 内容 | 决定 | 理由 |
|---|---|---|---|
| F1 | 槽位数 | 外壳 1.4.0 有 3 个槽位：0 直通、1 NCO、2 FIR。原有端口编号不变，新槽位接在后面：源 / 汇 4、5 为槽位 1、2，`PORT_RESET` 位 5、6，寄存器窗口 `0x3000`、`0x4000` | 两个模块串联需要各占一个槽位；不改编号，已有软件与测试不受影响 |
| F2 | 模块的寄存器接口 | 公共的 AXI4-Lite 从接口 `glidelink_module_axil.v`：给出写脉冲（地址、数据），读数据由模块按地址组合给出 | 每个模块只做地址译码，握手不再各写一遍 |
| F3 | 槽位清理 | 模块接口加 `flush` 输入：外壳清理槽位时只清数据通路（流水线、FIR 延迟线；NCO 相位回到 PHASE），寄存器保持 | Soapy 启动流时要清理链路上的槽位，若连寄存器一起复位，模块配置就丢了 |
| F4 | Soapy 的槽位清理 | 启动流时沿路由把链路上的槽位都清理（RX 往上游、TX 往下游），主机端口 0、1 都如此 | 串联的槽位之间也可能停着半个包；只清直接相连的槽位不够 |
| F5 | 数值格式 | sc16（`{Q, I}`）；NCO 4096 点表、幅度 32767，复乘结果加 2^14 右移 15 位后饱和；FIR 32 抽头 16 位实系数，40 位累加，输出加 2^(SHIFT−1) 右移 SHIFT 位后饱和 | 舍入与饱和在参考模型中逐比特规定；4096 点表实测最大寄生约 −72 dBc（参考模型，三个频率字，−71.5 ~ −71.9 dBc） |
| F6 | 未使能 | 数据原样通过（NCO 相位保持，FIR 样点不进延迟线） | 链路里的模块可以临时关掉而不改路由 |
| F7 | 反压 | 整条流水线随输出就绪一起推进（全局使能），FIR 延迟线只在有效样点上更新，流水线里的空拍不影响结果 | 简单、时序宽松；包尾不会卡在流水线里等下一个样点 |
| F7a | 槽位入口的隔离 | 外壳在每个槽位输入前放两级缓冲（`glidelink_skid.v`），流交换看到的就绪总是寄存器 | 槽位的输出与输入在流交换的多路选择器中相遇；模块的 `s_axis_tready` 若组合依赖 `m_axis_tready`（AXI4-Stream 允许），结构上就成了组合环路（第一次实现时 Vivado 报 LUTLP-1）。由外壳隔离，模块不需要遵守标准以外的规则 |
| F8 | 参考模型与测试向量 | 每个模块一个 `model.py`（NumPy），生成 NCO 的表（RTL 文件）与仿真向量；通用测试平台 `tb_module.v` 读向量、随机间隔与反压、核对数据与 `tuser` / `tlast` | 第 6 节的流程：参考模型是 RTL 与软件块的共同基准 |
| F9 | GNU Radio 块 | 每个模块一个软件块（调用参考模型）和一个代理块（按 `module.yaml` 中的寄存器名写槽位寄存器，不传数据）；参考模型与说明文件安装时从 `hw/modules` 拷入 Python 包 | 只有一份模型源码；软件块与 PL 模块逐比特一致，代理块替换前后输出可以直接比较 |

## 3. 结果

| 项目 | 方法 | 结果 |
|---|---|---|
| NCO 仿真 | `run_module_sim.ps1`，向量：正频率、负频率、未使能 | 3 组各 6000 个样点逐比特一致，`tuser` / `tlast` 随样点 |
| FIR 仿真 | 向量：随机系数含极值（饱和）、移位 0、低通、未使能 | 4 组各 6000 个样点逐比特一致 |
| 外壳级仿真 | `tb_shell4`：主机端口 1 → 槽位 1 → 槽位 2 → 主机端口 1，经外壳寄存器窗口配置 | 8000 个字与两个模型串联的结果一致；中途停发、`PORT_RESET` 清理主机端口 1 与两个槽位后，NCO 频率寄存器保留，同样的输入再次得到一致的输出 |
| 外壳回归 | `tb_shell_regs`、`tb_shell`、`tb_shell2`、`tb_shell3` 等 | 全部通过 |
| 软件块 | 分块流式处理与一次性运行参考模型比较 | 一致 |
| 上板硬件在环 | `modules_hil.py`，TX 板本地；RX 板经网络（PC） | 本地：NCO、FIR、两者串联各 262144 个字与参考模型逐字一致；经网络各 65536 个字一致 |
| 代理块替换 | `gr_proxy_swap.py`，PC 经网络（RX 板） | 软件块（A）与 PL 代理块（B）的输出各 131072 个样点，逐个相同 |
| 资源 | 实现后的分层利用率 | NCO 1076 LUT、392 FF、4 DSP（表综合为 LUT）；FIR 712 LUT、843 FF、64 DSP；每个槽位入口缓冲约 20 ~ 60 LUT、212 FF；整个外壳 7652 LUT、68 DSP；时序收敛（WNS +0.207 ns） |

## 4. 已知现象

- GNU Radio 的 Python 块必须在流程图运行期间保持引用；在 `connect()` 里直接构造的块会被回收，流程图启动时崩溃（段错误）。
- 经网络时，主机端口 RX 连续 1 s 收不到数据，libiio 0.23 的网络后端会断开与 iiod 的连接且不能恢复；主机端口源此时记录错误并结束（WORK_DONE），流程图可以正常结束。代理块替换测试在数据收完后就是这样结束的。
- 50 MSPS 全双工的 `ramp_loopback_iio`（CPU 逐样点生成并核对两个方向的数据）运行 100 s 时偶尔出错：TX 中途欠载一次，随后的数据不连续。
  外壳 1.4.0 下 12 次中 5 次、1.3.0 下 6 次中 1 次出现；30.72 MSPS 下 1.4.0 的 3 次与 30 s 的短测均无误。1.3.0 同样出现，
  不是本阶段的改动引入的；第 1 阶段的 300 s 无误是单次结果。两个版本的出错率差别在这样的样本量下不能下结论，原因（CPU 补 TX 缓冲不及时、
  DMA 缓冲个数等）另行排查。
