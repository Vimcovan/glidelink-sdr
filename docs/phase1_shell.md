# 第 1 阶段：PL 外壳（实施方案）

对应设计文档第 4 节与第 9 节第 1 阶段。验收标准：

1. 指定时刻发送的突发，在 RX 时间戳上对齐（经 AD9361 数字环回与两板空中各测一次）；
2. 在声明的采样率下长时间运行，溢出 / 欠载计数为 0。

## 1. 决定

| 编号 | 内容 | 决定 | 理由 |
|---|---|---|---|
| D1 | 通道数 | 先做 1R1T，外壳只接 `axi_ad9361` 的通道 0；驱动设为 1R1T 模式 | 设计文档 4.1；2R2T 之后扩展端口数即可 |
| D1a | 采样率上限 | 50 MSPS；开机跳过 TX 接口调校，用固定 TX 延时 | 第三方子卡 TX 线对 D4 / D5 在 245.76 MHz 接口时钟（61.44 MSPS）下余量不够，见 `hw/README.md` |
| D2 | 处理时钟 | 新增 PL 时钟 200 MHz（`pl_clk3`），用户模块与流交换都在这个时钟下 | 设计文档 4.6；单通道 61.44 MSPS 下每拍约 3.3 个时钟周期的余量，用户模块的时序比 250 MHz 宽松 |
| D3 | 流格式 | AXI4-Stream 32 位，`tdata = {Q, I}`（sc16），`tlast` 标记包尾；`tuser = {flags[7:0], timestamp[63:0]}` 只在包的第一拍有效 | 设计文档 5.1 |
| D4 | 主机端口的包格式 | 每个包前加 16 字节包头：字 0 = `{0xA5, flags[7:0], length[15:0]}`（length 为样点数），字 1 = 包序号，字 2 / 3 = 时间戳低 / 高 32 位；之后是样点。端口另有“原始模式”（不加包头），供不认识包头的工具（`iio_readdev`、gr-iio）使用 | 时间戳与突发标志随数据走，不需要另外的旁路通道；包序号用于检出丢包 |
| D5 | 流交换 | 自写多路选择器：每个汇端口一个路由寄存器，在包边界切换 | 端口少（第一版 4 源 × 4 汇），按包边界切换与“一个源只接一个汇”的约束容易做进逻辑；比 Xilinx AXIS Switch 便于仿真比对 |
| D6 | 主机端口 | 主机端口 0 就是 `cf-ad9361-lpc` / `cf-ad9361-dds-core-lpc` 的 DMA，现有 IIO 设备与 Soapy 模块不变。TX `axi_dmac` 用 AXI4-Stream 输出；RX `axi_dmac` 用 FIFO 写接口（AXI4-Stream 源时 Linux 驱动不启动该通道，见 `hw/projects/fmcomms2_pynqzu/glidelink_bd.tcl`），外壳在 DMA 有传输时（`xfer_req`）每两拍最多写一个字（400 MB/s），DMA 报告的溢出另行计数。主机端口 1（收、发各一）在 1.5 步加入，配一个小的 IIO 驱动 | 设计文档 4.5 候选 1；所有主机端口都走 libiio |
| D7 | 寄存器窗口 | AXI4-Lite，CPU 地址 `0x84B00000`，64 KB：`0x0000` 外壳、`0x1000` 流交换、`0x2000 + 0x1000·k` 槽位 k | 设计文档 4.7 |
| D8 | 槽位 0 | 直通模块（带标准寄存器），同时作为用户模块模板 | 设计文档第 9 节“一个直通模块槽位” |

## 2. 数据通路

```
RX: axi_ad9361 ch0 (采样时钟) ─► RX 流化：时间戳、切包、异步 FIFO ─► 流交换 ─► 主机端口 0 RX：加包头 ─► axi_dmac ─► 内存
TX: 内存 ─► axi_dmac ─► 主机端口 0 TX：解包头 ─► 流交换 ─► TX 流化：等发送时刻、异步 FIFO ─► axi_ad9361 ch0
                                                   ▲ ▼
                                             槽位 0（直通）
```

- 64 位采样计数器在采样时钟域，每个有效采样加 1；PS 经寄存器读（锁存高低两半）、写（对时）。
- RX 流化：包长可配（默认 4096 样点）。下游不能接收时整包丢弃，溢出计数加 1，下一个包的 flags 置“此前有丢包”。
- TX 流化：带发送时刻的包等计数器到达后开始送出；迟到的包按配置丢弃或立即发送，迟到计数加 1。
  FIFO 为空时输出 0；突发中途变空计为欠载，突发之间（上一个包带“突发结束”标志之后）的空闲不计。

- 流交换端口：源 0 RF RX、1 主机端口 0 TX、2 槽位 0 输出、3 主机端口 1 TX；汇 0 RF TX、1 主机端口 0 RX、2 槽位 0 输入、3 主机端口 1 RX。
  复位路由为 RF RX → 主机端口 0 RX、主机端口 0 TX → RF TX。没有汇选中的源被排空（数据丢弃，不反压）；
  一个源被几个汇选中时编号小的汇得到它。
- 主机端口 0 的包头模式（CONFIG 位 2 / 3）只在端口空闲时切换：先把该端口的路由断开，切换后再接回，
  流交换在包的开头接上。Soapy 模块在 `activateStream` / `deactivateStream` 中按这个顺序做。
- RX 包头中 flags 位 0 = 此前有丢包，位 7 = 包长超过 8192 被切开（其余部分作为后续包，时间戳接续）。
  TX 包头中 flags 位 0 = 定时发送，位 1 = 突发结束。

## 3. 寄存器（CPU 地址 0x84B00000 起）

| 偏移 | 名称 | 说明 |
|---|---|---|
| 0x000 | ID | `0x474C4B53`（"GLKS"） |
| 0x004 | VERSION | 1.1.0 起支持流交换、槽位与包头 |
| 0x008 | CAPS | `{槽位数, 主机 TX 端口数, 主机 RX 端口数, 射频通道数}` |
| 0x00C | SCRATCH | 读写测试 |
| 0x010 / 0x014 | TIME_LO / TIME_HI | 采样计数器；读 TIME_LO 时锁存高 32 位 |
| 0x018 / 0x01C / 0x020 | TIME_SET_LO / HI / CTRL | 写入设定值后 CTRL 位 0 写 1，在下一个采样装入 |
| 0x030 | CTRL_OUT | AD9361 `CTRL_OUT[7:0]` |
| 0x040 / 0x044 / 0x048 | RX_OVERFLOW / TX_UNDERFLOW / TX_LATE | 丢弃的 RX 包数、突发内欠载次数、迟到的定时包数 |
| 0x04C | HOST0_TX_ERR | 主机端口 0 TX 找包头时丢弃的字数 |
| 0x050 | RX_PKT_LEN | RX 包长（样点，默认 4096） |
| 0x054 | CONFIG | 位 0 RX 使能，位 1 丢弃迟到包，位 2 / 3 主机端口 0 RX / TX 包头，位 4 / 5 主机端口 1 RX / TX 包头 |
| 0x058 | HOST0_RX_OVF | 主机端口 0 RX：DMA 来不及收的字数 |
| 0x060 / 0x064 | HOST1_TX_ERR / HOST1_RX_OVF | 主机端口 1，同 0x04C / 0x058 |
| 0x05C | PORT_RESET | 写 1 清理（自动清零）：位 0 主机端口 0 RX；位 1 主机端口 0 TX，连同 RF TX 流化，并断开 RF TX 汇当时的连接；位 2 复位槽位 0 及其在流交换中的连接；位 3 / 4 主机端口 1 RX / TX。流中途被拆掉时 DMA 停在传输中间，外壳或槽位里留下半个包，流交换等不到包边界就不会换路由；每次启动流之前清理所用的端口，改动经过槽位的链路时一并复位槽位 |
| 0x1000 + 4j | ROUTE[j] | 汇 j 的源（`0xF` = 不接） |
| 0x2000 + 0x1000k | 槽位 k | 前 16 字节为标准寄存器（ID、版本、控制、状态） |

## 4. 实施步骤

| 步骤 | 内容 | 验证 |
|---|---|---|
| 1.1 | 外壳寄存器块：ID、版本、能力、64 位采样计数器、`CTRL_OUT`、计数器占位；新增 200 MHz 时钟；Soapy 模块加 `FPGA` 寄存器接口 | 仿真；板上读 ID 与计数器，按采样率核对计数速度 |
| 1.2 | RX / TX 流化（不带包头），接入 `axi_ad9361` 与主机端口 0，中间暂不经流交换；驱动改 1R1T | 仿真；`ramp_loopback_iio` 逐样点核对，50 MSPS 无错 |
| 1.3 | 流交换与槽位 0（直通） | 仿真；路由经直通模块后逐样点核对仍无错 |
| 1.4 | 时间戳与包头：RX 加包头、TX 按时刻发送；Soapy 模块的 `timeNs`、`END_BURST`、定时发送 | 仿真；数字环回下定时突发在 RX 时间戳上的位置误差为固定的流水线延迟（逐个突发一致）；两板空中测一次 |
| 1.5 | 主机端口 1（收、发各一）与小 IIO 驱动（`glidelink_host.ko`，IIO 设备 `glidelink-host1-rx` / `-tx`） | 主机端口 0 与 1 同时工作；长时间运行溢出 / 欠载计数为 0 |

每一步都先做仿真（xsim），再上板；比特流与设备树叠加按步骤更新，`load_overlay.sh` 加载方式不变。

## 5. 实测结果（TX 板，外壳 1.1.0）

| 项目 | 方法 | 结果 |
|---|---|---|
| 1.1 寄存器与采样计数器 | `sw/tests/shell_regs.py` | 2.5 ~ 50 MSPS 下硬件时间每秒走 1 s（误差 5×10⁻⁵ 以内），对时正确 |
| 1.2 流化（原始模式） | `sw/tests/ramp_loopback_iio`，AD9361 数字环回 | 50 MSPS 全双工 300 s，约 1.5×10¹⁰ 样点逐个无误；溢出 0，欠载只在停止时计 1 次 |
| 1.3 流交换与槽位 0 | 同上，路由主机端口 0 TX → 槽位 0 → RF TX | 50 MSPS 20 s 逐样点无误，槽位 0 计数 10⁹ 拍 |
| 1.4 定时发送与包头 | `sw/tests/timed_burst.py`，数字环回 | 20 个定时突发在 RX 时间戳上的偏移均为 12 个样点，迟到 / 欠载 / 溢出 / 包头错误均为 0 |
| 包头模式长时间接收 | `SoapySDRUtil --rate`（经 Soapy 模块的包头解析） | 50 MSPS 与 30.72 MSPS 各 180 s，溢出 0 |
| 包头模式发送 | 同上，TX | 50 MSPS 60 s，包头错误 0 |

`timed_burst.py` 在 Python 中收发两个线程，30.72 MSPS 以上 Python 本身跟不上（接收线程被发送调用阻塞），定时对齐因此在 10 MSPS 下验证；高采样率下的无损由上面两项 C / C++ 程序验证。

调试中定下的做法：

- 异步 FIFO 任一侧的复位都同时复位两侧（ADI 驱动初始化时会单独复位 `axi_ad9361` 一侧，只复位一侧的指针会让 FIFO 永久判满）。
- 流交换只在包边界换路由，停在包中间的端口永远到不了包边界：每次启动流之前用 `PORT_RESET` 清理所用的端口。
- Soapy 模块启动接收流时先关 RX 流化、建好 DMA 缓冲后再打开，流的开头既无丢包也无启动前的旧数据；默认缓冲区 65536 样点（排队 4 个，50 MSPS 下 5 ms 余量）。
- 被强行结束的程序可能留下包头模式开着；原始模式的测试程序开始时自行关掉包头、清理端口。

1.5 主机端口 1（外壳 1.2.0）：

| 项目 | 方法 | 结果 |
|---|---|---|
| 主机端口 1 单独 | `sw/tests/host1_loop_iio`，主机端口 1 TX → 槽位 0 → 主机端口 1 RX | 239.5 MB/s，20 s 逐字无误 |
| 两个主机端口同时 | 主机端口 0 跑 `ramp_loopback_iio`（RF 数字环回），同时跑 `host1_loop_iio` | 端口 0 50 MSPS 全双工 + 端口 1 限速 150 MB/s，120 s 两路均逐样点无误；端口 0 30.72 MSPS + 端口 1 不限速（252 MB/s），120 s 均无误 |
| 极限 | 端口 0 50 MSPS + 端口 1 不限速（240 MB/s） | 端口 0 出错（主机端口 0 RX DMA 溢出、TX 欠载）：两路合计约 880 MB/s 的内存流量加上 CPU 生成与核对数据，超出余量 |

计数器在流的开始 / 结束处会各动一次：欠载在流停止时计 1；主机端口 0 RX 的 DMA 溢出在 DMA 开停时增加；
主机端口 1 新的流的第一个字可能是上一次停在 DMA 内部的旧字。流进行期间计数不变、数据逐字无误。

尚未完成：两板空中的定时突发（两板没有共同的时间基准，只能比较突发间隔；RX 板仍是第 0 阶段的比特流）。
